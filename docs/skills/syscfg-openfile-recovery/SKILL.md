# SysConfig openFile Timeout Recovery

`openFile` fails after 60 s with `MCP error -32001: Request timed out` when SysConfig has no
full part number and package for the file. CCS then shows a **Select Device** or **Error
loading** dialog and waits for a click. Calling `openFile` again times out the same way.

## 1. Check the header

Read the `.syscfg` header comment. This skill applies when:

- there is no `@v2CliArgs` line; or
- `@v2CliArgs` has no `--package`; or
- its `--device` is not the part the table gives for its `--package` (e.g. `TMS320F2807x`, or
  `--package "F28004x_100PZ"`).

Otherwise the timeout has another cause, or the family is not in the table: stop and tell the
user.

## 2. Write `@v2CliArgs`

Take `--device` (the family), `--package` and `--context` from the `@cliArgs` line. Without
`@cliArgs`, take the family from IDEA `get_projects()` (`currentDevice`) and use the largest
package.

- **Package:** the `@cliArgs` package without its `<family>_` prefix (`F28004x_64PM` → `64PM`).
- **Device:** the family's part number, or the part listed for that package. Use it even when
  the project names a smaller part: the goal is only to open the file.

Replace the `@v2CliArgs` line, or add it directly below `@cliArgs` (above `@versions` when there
is no `@cliArgs`). The header's "Do not edit this file directly" notice does not apply: the
MCP cannot open the file.

```
 * @v2CliArgs --device "<device>" --package "<package>" --context "<context>"
```

Leave out `--context` when `@cliArgs` has none. Do not add `--variant` or `--board`.

## 3. Reopen

1. Call IDEA `close_editor` with the `.syscfg` path. While the stuck editor tab is open,
   `openFile` keeps timing out.
2. If it closed a tab, call `openFile` again. If it closed none, ask the user to close the
   `.syscfg` editor tab in CCS without clicking CONFIRM, and call `openFile` after they reply.
   The dialog's default part is often wrong, and CONFIRM writes it into the file.
3. Tell the user the line you wrote, and that the package is a guess when `@cliArgs` had none.
   SysConfig keeps the line and generates code for that part.
